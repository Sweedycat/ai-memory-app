# Cloud start instructions

Read AGENTS.md and the current owner's task. Run the prepared Install script (or
legacy setup script) with the current approved full SHA and pinned tool hashes.
Never rerun source selection over dirty or active task work. At each new task,
verify actual root, identity, branch, full HEAD and status before engineering.

Keep the platform-managed task branch when it already contains the approved
source. If the platform refresh changed source after installation, stop and
compare it with the approved SHA; do not reset or automatically merge. Do not
enable OMEGA_INITIAL_DETACH for maintenance or an active task.

Run `node tools/omega-runtime.cjs`. Record actual interface evidence separately:
registered `agent_type` invocation, generic delegation, native skill inventory,
hook inventory/trust/event execution and official quota telemetry. Files prove
definitions only. Linux alone does not prove a managed Cloud environment.

Use Mode A only with verified registered specialist invocation. Otherwise load
the relevant existing role with `node tools/omega-runtime.cjs --role ROLE` and
delegate only if the current runtime supports actual separate execution. Label
it Mode B role-guided. Load only the needed skill with `--skill NAME`; this is
manual repository instruction loading, not native activation. Read its local
references under the same checked-out repository. Never load arbitrary remote
instructions. Higher-priority rules and current owner scope always apply.

Before writes, agree a task, branch, immutable base SHA and exact owned files.
Use `--gate BASE_SHA ACTUAL_BRANCH TASK FILE...` as documented. This local check
is not native enforcement, a distributed lock, an approval or independent review.
Without native controls, sensitive transfers, credentials, signing, authentication,
privacy, destructive recovery and activation remain blocked pending a separately
reviewed controlled workflow. Ordinary bounded engineering needs focused checks
and independent frozen-diff review before checkpoint publication.

Do not start services, build APKs, install apps, deploy, buy credits or change
account settings. Apply the permanent founder quota policy in AGENTS.md Rule 10
equally to weekly and short-window limits, with mandatory stop at or below 1%.
Without official fresh quota observations complete one bounded milestone then stop; never infer
consumption from test counts or tokens. Phase 4 Cloud acceptance is still pending.
