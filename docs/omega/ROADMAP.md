# Approved roadmap

Priority source: the owner's approved development scope, summarized in the
[product inventory](../commercial-mvp-status.md) and governed by
[AGENTS.md](../../AGENTS.md). This is engineering scope, not launch dates,
commercial pricing or a promise that planned functionality is available.

| Order | Scope | Current boundary |
| --- | --- | --- |
| P0 | Preserve records; Notebook editor, encrypted persistence/recovery, key lifecycle and App Lock; strict checks and Android compatibility | Source foundations implemented and reviewed; physical acceptance and activation remain blocked |
| P1.1 | Rich readable people and interaction history | Searchable full history delivered; organization/duplicate/ambiguity improvements remain |
| P1.2 | Structured life administration and reminder management | Next bounded product milestone; schema, failure recovery and compatibility must precede activation |
| P1.3 | Grounded daily briefing and intelligent local retrieval | Follow-up overview exists; extend only to actual stored life records and clarify ambiguous people |
| P1.4 | Turkish/English localization | Translation-ready strings incrementally; reviewed catalogs/locale behavior still needed |
| P1.5 | Premium phone UX, accessibility and measured performance | Incremental improvement; no destructive UI rewrite |
| P2 | Android acceptance, onboarding/feedback/privacy UX and entitlement preparation | Device plan exists; entitlement boundaries/prices and releases require separate owner approval |
| P3 | Optional AI/BYOK, voice, proactive intelligence and supported wearables | Conditional future work, inactive; cannot delay the standalone MVP |

Native acceptance preparation can proceed independently as documentation.
Actual device actions, builds, signing, installation and activation need their
separate task-specific gates. Do not weaken a blocked P0 capability to start a
later feature. Independent safe source work may proceed only when authorized.

Retain local standalone value and existing entitlements. Financial and payment
decisions remain in the [financial](../financial-policy.md) and
[payment](../payment-strategy.md) policies, without duplicating commercial plans
here. No paid service, live billing or externally billed AI is activated by this
roadmap. Current task ends after documentation synchronization; implementation
requires the next authorized development task.
